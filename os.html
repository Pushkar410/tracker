What is an Operating System?
📘 Formal Definition (from PDF)

"An operating system is a piece of software that manages all the resources of a computer system, both hardware and software, and provides an environment in which the user can execute his/her programs in a convenient and efficient manner by hiding underlying complexity of the hardware and acting as a resource manager."

In plain English: The OS is the manager between you and the hardware. You click Save — you don't need to know which disk sectors are free, how to write magnetic data, how to verify the write. The OS handles ALL of that silently.

┌───────────────────────────┐ │ USER │ ├───────────────────────────┤ │ APPLICATION PROGRAMS │ ← WhatsApp, Chrome, Games ├───────────────────────────┤ │ OPERATING SYSTEM │ ← The Manager ├───────────────────────────┤ │ COMPUTER HARDWARE │ ← CPU, RAM, Disk, Screen └───────────────────────────┘
Without an OS — 3 Big Problems
⚠️ No OS = Chaos
  • Bulky complex apps: Every app must include hardware interaction code. A calculator would need thousands of lines just to draw on screen.
  • Resource exploitation: One greedy app grabs ALL RAM and CPU. Nothing else can run.
  • No memory protection: Any app can read or overwrite any other app's data. No privacy at all.
Two Core Jobs of an OS
Abstraction — "Hiding complexity"
The OS hides all the ugly hardware details. You just click a button — the OS quietly handles the disk sectors, memory addresses, CPU instructions needed.
Like driving a car — you just steer. You don't manually control each tyre, the suspension, the differential. The car abstracts all that away.
Arbitration — "Resource Management"
Multiple apps want CPU, RAM, and printer at the same time. The OS decides who gets what, when, and for how long. A fair referee.
Like a traffic police officer at a busy junction — decides which cars (apps) go when, preventing crashes and ensuring everyone gets through.
OS Goals (from PDF)
  • Maximum CPU Utilization: Keep the CPU busy. An idle CPU = wasted resource.
  • Less Process Starvation: Starvation = a process keeps waiting and NEVER gets CPU time. Must prevent this.
  • Higher Priority Job Execution: Important tasks must get CPU before low-priority background tasks.

    Program, Process, Thread
    Program
    A compiled, executable file stored on disk. Not running. Just instructions in a file.
    Like a recipe written on paper — just instructions. Not being cooked yet.
    Process
    A program loaded into RAM that is currently RUNNING. The OS has created a full environment for it (memory, stack, heap, PCB).
    The recipe now being actively cooked on the stove. Alive. Consuming gas (CPU), using pots (memory).
    Thread
    A single sequence of instructions running INSIDE a process. One process can have many threads. Threads share the process's memory — they are "lightweight processes" because creating a thread is much cheaper than a full process.
    One cook doing 3 things simultaneously: chopping (Thread 1), stirring (Thread 2), watching the timer (Thread 3). Same kitchen (memory), same cooking session (process).
    Multitasking vs Multithreading
    FeatureMultitaskingMultithreading
    ConceptMultiple PROCESSES context switchedMultiple THREADS within one process context switched
    MemoryEach process has OWN isolated memory. Full protection.All threads SHARE the same process memory. No isolation.
    CPUs1 CPU sufficient≥1 CPU (best with multiple)
    Context SwitchSLOW — full memory address space changes, cache flushedFAST — only PC + registers + stack change, cache preserved
    OS allocatesSeparate memory and resources per programMemory allocated once to process; threads share it
    What is the Kernel?
    💡 Definition (from PDF)

    A kernel is that part of the operating system which interacts directly with the hardware and performs the most crucial tasks. It is the heart/core component. The very first part of OS to load on startup.

    Kernel Space
    Where the kernel runs. FULL access to all hardware. Privileged mode. No restrictions.
    User Space
    Where application software runs. NO direct hardware access. Apps must ask the kernel via system calls.
    Contains GUI (buttons you click) and CLI (commands you type in terminal).
    Shell
    A command interpreter — receives commands from users and gets them executed by the kernel. When you type mkdir folder1, the shell passes this to the kernel's file management module.
    4 Functions of the Kernel
    1. 1
      Process Management: Scheduling, creating, deleting, suspending, resuming processes and threads. Providing mechanisms for synchronization and communication.
    2. 2
      Memory Management: Allocating and deallocating memory space as needed. Tracking which process owns which memory.
    3. 3
      File Management: Creating/deleting files and directories. Mapping files to secondary storage. Backup support.
    4. 4
      I/O Management: Buffering (temporary storage within one job — YouTube buffering), Spooling (queueing between two speed-different devices — print queue), Caching (fast-access copies — browser cache).

    IPC — Inter Process Communication (IMPORTANT — Often Asked)
    💡 What is IPC?

    Two processes execute independently with their own memory space (memory protection). But sometimes they NEED to communicate — e.g., a browser asking the file system to read a file, or a producer process sending data to a consumer process.

    IPC is done using two methods:

    Method 1 — Shared Memory
    A region of memory is established that can be accessed by BOTH processes. One process writes to this shared region, the other reads from it. It's the FASTER method because once the shared memory is set up, no kernel involvement is needed for each communication — processes directly read/write.
    Like two people sharing a whiteboard. One writes a message. The other reads it. No middleman. Very fast but needs synchronization (semaphores/locks) to prevent race conditions.
    Method 2 — Message Passing
    Processes communicate by SENDING and RECEIVING messages through the OS kernel. Process A calls send(message). Process B calls receive(message). The kernel acts as the post office — it receives the message from A and delivers it to B.
    Like two people sending letters through a post office (kernel). Safer because there's no shared memory to corrupt, but SLOWER because every message goes through the kernel (requires system calls).
    FeatureShared MemoryMessage Passing
    SpeedFASTER — no kernel needed per communicationSLOWER — every message goes through kernel
    Ease of useHarder — programmer must handle sync (locks/semaphores)Easier — OS handles communication details
    Who manages it?Programmer (must set up shared region and synchronize)OS kernel (handles send/receive)

    RiskRace conditions if synchronization is wrongMessage lost or delayed if kernel has a bug
